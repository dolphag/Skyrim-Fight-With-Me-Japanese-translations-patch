# 翻訳方針(Fight With Me / Path of the Companions / Walk With Me 共通)

作成: 2026-10-27(下書き)。3 つの日本語化パッチの訳を揃えるための方針。人間の翻訳者にも LLM にも、これだけ読めば同じ品質の訳が出せることを目指す。

- 対象 MOD と方式
  - Fight With Me(FWM)・Path of the Companions(Paths): 原作が外部ファイルに分けたメッセージの日本語版(`*_JAPANESE.txt`)を置く。表は各リポジトリの `translations_en_ja.csv`(列 `en,ja`)。
  - Walk With Me(WWM): 現状は DLL パッチ。表は `translations_en_ja.csv`(列 `English,Japanese`)。外部ファイル化されたら FWM と同じ方式に移る見込み(未確認)。
- 各項目の状態を 3 つに分ける。
  - **【方針】**: 決定済み。守る。
  - **【現状】**: 2026-10-27 時点の CSV を集計した実態(数字は当日の実測)。方針ではない。
  - **【要決定】**: まだ決まっていない。決まるまで、既存の訳に合わせる。

## 1. 優先順位
**【要決定】D0** 次の順は、今の訳の実態から私(Claude)が起こした案で、まだ了承を得ていない。
1. **意味が正しい**(数値・条件・対象を落とさない)。
2. **画面に収まる**(原文の約半分の長さが実績。窮屈な場所は短くする)。
3. **用語が揃っている**(`docs/GLOSSARY.md`)。
4. **自然な日本語**(日本語として意味が伝わること)。

## 2. 文体
**【方針】原文の形に合わせる。** 文体は使われる場所ではなく、まず原文がどういう形かで決まる。
- 原文が断片(句点で終わらない名詞句・ラベル・見出し)→ 体言止めで句点なし。例: 習熟済み、やり直す、従者を選ぶ。
  - 【現状】FWM で、英語が断片の 438 項目のうち、日本語が句点なしだったのは 98%。
- 原文が文 → 文で訳す。
  - 【現状】2 文以上の 80 項目のうち、です・ます調は 84%(67 項目)。
- 数値は半角。全角数字は使わない(全角数字 0 件)。
- **【要決定】D1** 原文が句点で終わる 1 文のとき、です・ます調か常体(「〜する。」)かは、原文だけでは決まらない。【現状】364 項目で です・ます 59%、常体 39%、句点なし 2%。決める材料は「アビリティ説明どうし」など、同じ画面・同じ種類の文を揃えること。基準を作る。
- 二人称: 「あなた」が使われている例がある(「あなたの前で戦線を守り」)。原文に you があるときの扱いは未整理(**【要決定】D1c**)。

## 3. 用語
- 正本は `docs/GLOSSARY.md`。変更はユーザー(パッチ作者)の了承が要る。
- 公式日本語訳(バニラの Skyrim 日本語版)がある語は、それに合わせる(時間減速、治癒の手 など)。入手元: WWM の `CLAUDE.md` は「Fandom wiki の一覧(ファンによる抽出であり公式サイトではない)」と記している。
- 公式訳が無い語(MOD 独自の名前)の付け方:
  - **【現状】** 意訳(刃の道、戦意喪失、最後の砦、癒しの円)と音訳(ケイオスダウン、ウォークライ、マグナス)が両方ある。
  - **【要決定】D2** 原作者に渡したあとは、「暫定」の語を残すと対応に困る。そこで、判断を規則にして、迷いなく同じ訳が出るようにする。案(上から順に当てはめ、最初に当てはまったもので決める):
    1. バニラの Skyrim 日本語版に同じ名前・語がある → その表記。確認できない場合は次へ。
    2. 人名・神名・地名などの固有名詞 → 音訳(カタカナ)。
    3. 一般の英単語を組み合わせた名称(Weak Will、Last Bastion、Healing Circle)→ 意訳。
    4. 固有名詞と一般語を組み合わせた名称(Azura's Moon、Kynareth's Maw)→ 固有名詞の部分に 2、一般語の部分に 3 を当てて連結する(アズラの月、カイナレスの顎)。
    5. 日本語のゲーム用語としてカタカナが定着している語(タンク、ヒーラー、シャウト)→ カタカナ。
    - 既存の訳で検算した結果、**ウォークライ(War cry)とケイオスダウン(Chaos Down)は、規則 3 では意訳になるはずで、現状の音訳を説明できない**。例外として規則に書くか、訳を変えるか、作者の判断が要る。
- **【現状】** `docs/GLOSSARY.md` の「0.5.0 / Paths 1.0 で追加」の語は「暫定。実機確認前」。D2 が決まったら、規則で決まる状態にして「暫定」を無くす(**【要決定】D1b** 確定の手順)。原作者に渡す時点で「暫定」が残っていない状態を目標にする。
- 固有名詞(MOD 名・ボタン名・キー名): 原作の英語のまま。Esc、Tab、LB + Y、Walk With Me など(FWM で 20 項目が英語のまま)。

## 4. 書式欄・記号
- **【方針】** `{}` `{0}` `{:.0f}` `%.0f` `%d` などの書式欄は、種類と数を英語と一致させる。順序を入れ替える必要があるときだけ番号付き(`{1}{0}`)にする。FWM/Paths は `lang_build.py` が機械検査する。WWM は `verify.py`。**検査が通らない訳は出さない**(表示が壊れうる唯一の項目)。
- `\n` は実際の改行として保持する(CSV では実改行)。
- **【方針】** 矢印 `→` は使わない(HUD のフォントに無い。0.3.0 での観察。0.5.0 は未確認)。`：` や `、` で代用する。
- **【方針】** `%.0f units` は `%.0f ユニット`(数値と単位の間に空白あり)に統一する(2026-10-27 のご指示)。FWM と Paths の CSV は現在 `%.0fユニット` で、変更が必要(**未実施**。訳が変わるので、版を上げて実機確認を経る。Paths は別リポジトリ)。
- **【要決定】D3** 原文が `10 m` のように数字と単位の間に空白を置いている 3 項目(FWM)は、現状の日本語が `10m`(空白なし)。「原文に合わせる」ならば `10 m` になる。助数詞(5本、{:.0f}% など)は【現状】空白なし。
- 括弧: `「 」` は、シャウト名・ボタン名などの引用に使われている(FWM 13 項目)。

## 5. 長さと折り返し
- **【方針】** 折り返しは ASCII の半角スペースでしか起きない。長文には文節の区切りに半角スペースを入れる(FWM/Paths は `lang_build.py` が日本語形態素解析で自動で入れる。CSV の `ja` には入れない)。
- 表示倍率・位置は、FWM/Paths では訳から調整できない。WWM は DLL の定数で調整できる(日本語は英字より小さく見える)。
- 窮屈な場所は訳を短くする(これは既存のルール)。体言止めにするのはその手段の一つ。

## 6. 使える文字
- FWM/Paths: 【現状】`tools/jp_kanji.txt` の範囲内に限り、範囲外の漢字はひらがなにする(`lang_build.py` が失敗で知らせる)。ゲーム由来の文字列は変えられないので、利用者には EnableChinese を勧めている。**これは本来あるべき状態ではなく、暫定の措置**。SKSE Menu Framework 側に修正を依頼済み(作者の申告。こちらでは未確認)で、取り込まれれば制限が無くなる可能性がある。それまでは範囲を守る。
- WWM: 【現状】置き換えフォント(Noto Sans JP のサブセット)に、訳に使った漢字を取り込む。範囲の制限は無い。
- **【要決定】D4(保留)** 流動的なので、SKSE Menu Framework と WWM の外部ファイル化の動向を見て決める。

## 7. 訳さないもの
- ホイールのモード名・タイル名(WWM: Natural / Lead など)、コード内に埋め込まれて安全に置換できない文字列、ログ。
- 原作が一覧を通していない文字列(FWM のパーティ設定ページのドロップダウン)。原作者への報告案は `docs/upstream-report-draft.md`。

## 8. LLM に下訳させるとき
入力: ①この文書 ②`docs/GLOSSARY.md` ③既存の CSV(訳済みの項目。**同じ語は同じ訳にする**ため必ず渡す) ④翻訳する項目(`lang_build.py` の「未訳」)。
- 訳済みの項目は変えない。新しい項目だけ訳す。
- 書式欄・`\n` はそのまま写す。数値は変えない。
- 用語集に無い名前は、D2 の規則のどれを当てたかを添えて返させる(「暫定」にはしない)。規則で決まらない語だけ、迷った箇所として返す。
- 原文が断片なら体言止め、文なら文で訳す(第 2 節)。
- 返すもの: CSV の行 + 迷った箇所の一覧(なぜ迷ったか)。
- 出力は必ず検査(FWM/Paths は `lang_build.py`、WWM は `verify.py`)を通す。通らなければ人間が直す。

## 9. 確認の水準
- **【方針】** 利用者に出す版は、実機で確認する(スクリーンショットと所見)。
- 下訳のまま出す場合(将来の想定)は、そう明記する。読者に「未確認の機械翻訳」と分かるように。利用者はゲームの利用者で、GitHub の利用者とは限らないので、修正は Nexus の投稿(コメント欄)で受ける。

## 10. 3 リポジトリ間の差異(2026-10-27 時点)
- FWM と Paths の CSV: 共通 821 項目、訳の違い 0。Paths の CSV は FWM の上位集合(1099 項目 ⊃ 822 項目)。二重に保守しており、ずれる余地がある。**【要決定】D5** 共通部分をどちらかに寄せるか。
- **【方針】** MOD 間で同じ英語でも、表示される箇所によって適した訳が違うことがあるので、無理には揃えない。揃えるのは、GLOSSARY の用語と、次の 2 点。
  - Troubleshooting は `トラブルシューティング` に統一する(FWM/Paths の `問題の調査` を変更。**未実施**。D3 と同じ手順)。
  - `%.0f units` の空白(第 4 節)。
- FWM と WWM の共通項目 14 のうち、訳が違う 5 項目の扱い(2026-10-27 の判断)。
  - COMPANIONS(従者 / 従者一覧)、Setting(設定 / 設定項目): どちらも正解になりうる。表示箇所による。揃えない。
  - Spread out(分散 / 広げる): 文字数での調整もありうる。揃えない。
  - Troubleshooting、`%.0f units`: 上のとおり統一。
- 列名: FWM/Paths は `en,ja`、WWM は `English,Japanese`。
- 用語の使用状況(WWM): 隊列 12 件(FWM 1 件)、仲間 2 件(FWM 0 件。「誰が仲間にした従者でも」の動詞用法)。
